# Postmortem: Data Honesty + Source Triangulation Pass

**Dates:** May 9–10, 2026
**Branch:** `main` (no feature branch — small atomic commits direct)
**Final state:** 40 spots (was 28), every Tier-1 audit item closed, all NorCal regions triangulated against Stormrider + Surfline.

## What we set out to do

Audit the codebase for hard-coded data values that pretended to be live, fix them, then take a data-quality pass across all 28 surf spots using Stormrider Guide and Surfline as cross-checks.

## What we shipped

### Tier-1 audit (data lying to the user)
- **Water temp + wetsuit** were string literals (`"54"` / `"4/3 mm"`). Wired to live `waterTempF` from the buoy response with a NorCal-tuned `wetsuitForWaterF()` helper.
- **Mavericks watch panel** was static prose ("20ft+ by Friday 4am"). Now templated from `mavTimeline` peak hour. Later gated behind real contest-grade thresholds (Hs ≥ 15ft, period ≥ 15s, WNW direction) so the panel only appears on actual events instead of any small NW swell.
- **`hourLabel`** was anchored to `baseHour=6` with hardcoded `"Fri"`/`"Sat"` prefixes. Rewrote to use `Date.now()` + real day-of-week. Affected every chart axis, GO NOW window, Best Windows strip, Mavericks watch line — all were quietly lying about what time it was.
- **Loading-state honesty** — promoted the in-memory conditions cache to localStorage with a `v1:` prefix. Reloads now hydrate from the user's last real forecast on first paint instead of synthetic mock numbers. Cache key includes spot IDs so adding/removing a spot invalidates cleanly.
- **Air-temp fallback** — primary buoy 46026 doesn't have a met sensor (only 46012 does). Header read `—°F` whenever top-pick was a Marin/Bolinas spot. Added fallthrough to any buoy reporting `airTempF`.

### Tier-2 schema cleanup
Promoted three substring-keyed coefficients to typed `Spot` fields and generalized one special-case rule:
- `shadowFactor?: number` (0–1, swell shelter from optimal direction)
- `sandMobility?: number` (0–1, contour shift week-to-week)
- `specialRules?: SpecialRule[]` — currently `'falling-tide-rip'` discriminated union; was inline `if (spot.id === 'bolinas-groin' && ...)` in two places.

### Tier-4 region rename
Split the old `marin-sf` region into separate `marin` (Bolinas, Stinson, Muir, Rodeo) and `sf` (Fort Point, Deadmans, Kelly's Cove, Ocean Beach N/C/S). Better matches county geography. Map header reads "R3 · MARIN" and "R4 · SAN FRANCISCO" (full name in the section header; spot-level `regionLabel` stayed `'SF'` to avoid card-text wrapping).

### Source triangulation: 40 spots × Stormrider + Surfline
Every Tier-1 surfable NorCal spot ran through both sources. Real corrections caught — not just refinements:

- **Mavericks** had `optimalTide: 'high'` and `offshore: 70`. Both wrong. Both sources clearly say low-incoming + east. Was scoring contest days badly.
- **Montara** had `offshore: 45` (NE). Both sources say E (90°). Same systematic 45° bug also caught at Francis Beach.
- **Stinson** had `optimalPeriod: [14,18]` (groundswell-only). Surfline explicitly says "Windswells work wonders." Shifted to `[10,14]`.
- **Linda Mar's** unique south-funnel valley (S/SW winds become offshore) was undocumented; flagged in INSIGHTS.
- **Bolinas Jetty's** difficulty was 2 (Beginner) but Stormrider rates Intermediate; the hazards (sharks, localism, currents) supported the bump to 4.

## Working principles that locked in this session

These came up explicitly and are now part of how the project gets built:

1. **"This is not a discovery app."** No browse/recommend affordances. Set-and-forget UX. The user already knows their spots.
2. **Data lands when it makes scores more accurate.** Editorial ratings (stormriderStars, Surfline rating, crowd factor, vibe) serve users discovering new spots. They don't help someone checking whether to drive to a spot they already surf. Cut. We dropped `stormriderStars` after adding it for this exact reason.
3. **Drivable AND in rotation.** Spot-inclusion filter. Stormrider's coverage isn't sufficient; even "expert nearby" isn't (Mystos passed only because of the vacation home). Boat-only is a hard no.
4. **Green/yellow/red = quality everywhere.** The cross-screen color rule. `qualityColor` (0–1 scale) and `scoreColor` (0–100 scale) share thresholds. Fixed colors (pacific blue, phosphor green) are reserved for non-quality identity (data lines, constant references).
5. **Verify, don't trust.** Every commit checked in preview before push. Caught the air-temp fallback bug live (header was reading `—°F` without us realizing).

## What didn't go well

- **Multi-step refactors with hot-reload churn** produced spurious React error boundary stacks. The "VectorsPanel extraction" left ghost errors in the console buffer that looked like real failures. Reload always cleared them. Worth flagging if it happens again.
- **Stormrider has known structured-field errors.** Princeton Jetty's "LOW TIDE ONLY" reads like a copy-paste bug — the wave geometry is a shallow wedge that needs mid-high tide, which Surfline correctly reports. We trusted Surfline over Stormrider in that one case.
- **The score model still has miscalibration.** `computeScore`'s `watchOnly` path maxes the size component at 8ft swell — fine for flagging "this is a Mavericks day" but laughable as an actual height threshold for the contest. Worked around it by gating the panel on raw size/period/direction instead of score, but the underlying formula needs tuning.
- **Drag and drop ordering for FAVORITES** isn't done — that's the next big feature. Backlog item #10.
